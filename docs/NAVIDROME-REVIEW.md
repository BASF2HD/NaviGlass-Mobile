# Mobile library and audio review — refreshed 0.2.5

The review traced the app-owned native code, WebView bridge, browsing and queue state, renderer integration, storage/scan paths, radio handling, manifest/network policy, build configuration and native/JVM checks. Bundled third-party library internals were not independently audited. Original desktop repositories were read for parity and were not modified for this mobile change.

## Remembered connection

Remember login encrypts the last attempt, including when the network fails. URL and username are prefilled; a saved-password placeholder lets native code reconnect without returning the password to JavaScript. The exact server/account must match. Unchecking removes persisted credentials and prevents restoration after process death while retaining a running session in memory. Disconnect retains an opted-in login for reconnection. DNS, certificate, timeout and reachability failures have distinct guidance. Synthetic HTTPS checks cover prefill, retry, recreation, unavailable-server recovery, account matching and session-only storage. Ten JVM tests, seven native checks and Android lint pass for this update.

## Verification

The isolated Android 15 emulator fixture contains 5,001 albums, a starred album on page two, 301 favourite songs across two albums, two artists, two server playlists and two server radio stations. It checks persistent album/playlist cache hits, no per-album song requests for grouped Artists, cancellation, immediate menu changes, remembered grouping across Activity recreation, grouped playlist playback across two albums, unchanged playback queues while browsing, and automatic detection of a new album/song while preserving the selected cover. It also checks complete imports, full header totals, ticks, compact rows, remote star/unstar, device/remote isolation, legacy playlist-track migration, encrypted login restoration and disconnect authorization.

Native audio checks use non-silent synthetic M4A/AAC, stereo 48 kHz WAV and FLAC files. A synthetic unsupported ALAC source exercises server conversion to FLAC. Both negotiated-stream and older-server fallback cases require selected audio tracks, nonzero and increasing rendered decoder-buffer counts, advancing playback, nonzero volume and no player error. Tests cover seeking, remote background playback and automatic transition from the last favourite in one album into the next favourite album with repeat/shuffle off. Existing local playback/mode/lifecycle and touch/layout suites also pass. Nine JVM checks and Android lint pass.

## Limits and operation

This fixes confirmed import and stream-selection defects. The Honor phone's exact model, Android version, original codecs and acoustic output were not available, so its reported silence is not claimed reproduced or certified resolved. Android codec behavior, speaker/headphone/Bluetooth routing and server transcoding configuration still require a handset listening check. Playback negotiation follows the [OpenSubsonic decision API](https://opensubsonic.netlify.app/docs/endpoints/gettranscodedecision/) and [stream API](https://opensubsonic.netlify.app/docs/endpoints/gettranscodestream/); device support follows [Media3 format support](https://developer.android.com/media/media3/exoplayer/supported-formats).

After installing over the existing APK, open the remote source or use Settings → Refresh Navidrome library. First upgrade loads complete remote metadata; manual refresh also imports changes made in the web app. The saved catalog appears immediately. A separate foreground worker refreshes metadata after five minutes without blocking menu reads; changed snapshots invalidate account-scoped detail caches. Manual Settings refresh invalidates details immediately. Cached detail responses expire after 30 minutes and are bounded to 128 files / 32 MiB. The cache stores metadata, not audio. Song browsing/search still uses 200-result pages, although totals and favourite imports are complete. Remote queues have a 10,000-track limit. Server playlists and radio stations are read-only, with no offline audio downloads. Imported HTTP radio addresses remain visible but require an HTTPS address for playback in the published build.

VersionName **0.2.5**, versionCode **8**, application ID and signing certificate remain unchanged. Installing the refreshed APK retains app data. Earlier authorized read-only personal-server checks succeeded in Android, including authentication, complete import, encrypted restoration and the actual Connect form. The reported phone could not open the address in its browser, so that handset's reachability remains unresolved. No private endpoint, credentials, signing keys or test TLS key are packaged in the release APK.
